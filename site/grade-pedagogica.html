📘 Plano Pedagógico

Este documento define a metodologia do Laboratório de Tecnologia Social. Ele serve como referência para voluntários, professores e gestores do projeto.

1. Princípios

  1. Gratuidade total — nenhuma aula, material ou ferramenta pode ter custo para o aluno.
  2. Acesso aberto — todo conteúdo é público e reutilizável (licença MIT).
  3. Aprender fazendo — aulas baseadas em projetos, não em teoria pura.
  4. Inclusão — acolher iniciantes, meninas e grupos subrepresentados na tecnologia.
  5. Segurança — proteção de menores em primeiro lugar (ver seguranca-criancas.md).

2. Metodologia

Cada módulo segue o ciclo:

Apresentação do problema  →  Exploração  →  Mão na massa  →  Projeto  →  Mostra de resultados
  • Aulas de 60 a 90 minutos.
  • Ritmo semanal (presencial ou online).
  • Uso de ferramentas gratuitas: Scratch, Python, Google Colab, GitHub Pages, Figma.
  • Avaliação é formativa: projetos e participação, nunca prova eliminatória.

3. Objetivos de aprendizagem

Exploradores (8–12)

  • Compreender o que é um computador e como ele pensa (lógica).
  • Criar animações e jogos simples.
  • Montar circuitos básicos e entender sensores.
  • Publicar uma página web própria.

Makers/Devs (13–20)

  • Programar em Python com confiança.
  • Construir sites e pequenas aplicações web.
  • Aplicar noções de testes de software (QA) e qualidade.
  • Analisar dados e contar histórias com números.
  • Conceber e entregar um projeto de impacto social em open source.

4. Cronograma sugerido

TrimestreExploradoresMakers/Devs
1Lógica + ScratchPython + lógica
2Robótica/IoT básicaWeb (HTML/CSS/JS)
3Primeiro siteQA + Ciência de Dados
4Projeto finalProjeto social open source

5. Materiais e infraestrutura

  • Computadores ou notebooks (parcerias com escolas/empresas).
  • Conexão à internet.
  • Contas gratuitas: GitHub, Google Colab, Scratch.
  • Para IoT: kits básicos (Arduino/Pico) doados ou emprestados.

6. Avaliação e evolução

  • Feedback semanal dos alunos (formato lúdico).
  • Reunião mensal de voluntários para melhorar o conteúdo.
  • Este repositório é a "fonte da verdade": melhorias via pull request.
